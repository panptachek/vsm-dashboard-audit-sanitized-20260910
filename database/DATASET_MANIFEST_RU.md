# Манифест синтетической БД

## Гарантии

- Дамп создан из новой пустой БД после восстановления только `schema.sql`.
- Единственные добавленные строки находятся в `seed_synthetic.sql`.
- Данные production не копировались и не обезличивались: их в наборе нет.
- Все UUID фиксированы для воспроизводимости.
- Доменные коды и номера помечены `DEMO`, комментарии - `SYNTHETIC DATA`.

## Покрытые сценарии

- План, проектный объем и факт по линейному объекту.
- Работа и перевозка по ИССО.
- Обычный и крупный песок как разные материалы.
- Собственная и привлеченная техника.
- Полная смена `11` часов, частичная смена `5.5` часов и `NULL`, означающий
  применение нормы полной смены.
- Две работы одной единицы техники по `5.5` часа.
- Перевозка из карьера на объект и на промежуточный склад.
- Пикетажные сегменты, алиасы, расценки и нормы производительности.

## Намеренные пробелы для аудита

- `DEMO_GRADING` не имеет расценки.
- План по `DEMO_GRADING` не связан с проектной строкой.
- Факт `DEMO_GRADING` не имеет подрядчика.
- Для этого факта не создан пикетажный сегмент.
- Часть `work_hours` равна `NULL`; аудитор должен подтвердить единое правило
  интерпретации `NULL = 11 часов` во всех API, расчетах и выгрузках.

Пустые операционные таблицы не считаются ошибкой набора. Аудитор должен отдельно
определить, какие из них являются обязательными для минимального продукта, а
какие относятся к историческому или специализированному функционалу.
